# ADR-003: 使用 drift (SQLite) 做本地持久化

## 状态

Accepted

## 背景

应用需要持久化订阅节目、单集、下载任务、播放进度、用户设置等数据。需要一个本地数据库方案。

## 选项

| 选项 | 优点 | 缺点 |
|------|------|------|
| drift (SQLite) | Flutter 生态最成熟的 SQL 封装；类型安全；跨平台 | 需要写表结构迁移 |
| Hive | 纯 Dart，无原生依赖，速度快 | 复杂查询弱，类型安全不如 drift |
| ObjectBox | 高性能 NoSQL | 对简单 CRUD 场景过重 |
| SharedPreferences + 文件 | 简单 | 关系数据管理困难，易乱 |

## 决策

选择 **drift** 作为本地数据库。

## 理由

1. **关系型数据**：订阅、单集、下载任务、标签之间有关系，SQL 更适合。
2. **类型安全**：drift 生成类型安全的 Dart API，AI 写代码不容易出错。
3. **跨平台**：SQLite 在 Android 与 Windows 上都原生支持。
4. **查询能力**：复杂的筛选、聚合、状态查询容易表达。

## 影响

- 需要定义表结构和迁移脚本。
- 需要学习 drift 的 DAO/Repository 模式。
- 测试时需要使用 drift 的内存数据库支持。
